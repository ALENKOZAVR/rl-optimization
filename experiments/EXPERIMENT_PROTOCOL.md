# Протокол сравнительного эксперимента DE и RL-DE

## 1. Цель эксперимента

Подготовить воспроизводимый и проверяемый протокол сравнения пяти алгоритмов:

1. DE/rand/1/bin
2. DE/best/1/bin
3. DE/current-to-best/1/bin
4. Random-DE
5. RL-DE (Q-learning)

Цель текущего этапа — не «получить лучшие числа», а зафиксировать методику и проверить инфраструктуру запуска/логирования.

## 2. Какие алгоритмы сравниваются

- **Фиксированные DE**: одна стратегия мутации на весь запуск.
- **Random-DE**: стратегия выбирается случайно на каждом поколении.
- **RL-DE**: стратегия выбирается Q-learning агентом по состоянию поиска.

Во всех вариантах используется одна и та же база `thefittest 0.2.7`.

## 3. Какие функции используем

Поддерживаются:

- Sphere
- Ackley
- Rastrigin
- Rosenbrock
- Schwefel

Выбраны стандартные математические формы и **приняты для нашего эксперимента** области:

- Sphere: \(\sum x_i^2\), минимум 0 в \(x=0\), рекомендованная область \([-5.12, 5.12]\)
- Ackley: классическая форма с \(a=20, b=0.2, c=2\pi\), минимум 0 в \(x=0\), область \([-32.768, 32.768]\)
- Rastrigin: \(10n + \sum(x_i^2 - 10\cos(2\pi x_i))\), минимум 0 в \(x=0\), область \([-5.12, 5.12]\)
- Rosenbrock: \(\sum 100(x_{i+1}-x_i^2)^2 + (1-x_i)^2\), минимум 0 в \(x=(1,\dots,1)\), область \([-5, 10]\)
- Schwefel: \(418.9829n - \sum x_i\sin(\sqrt{|x_i|})\), минимум около 0 в \(x_i \approx 420.9687\), область \([-500, 500]\)

Отдельно зафиксировано: **Sphere упоминается в тексте статьи, но отсутствует в таблице итоговых результатов**.

## 4. Какие параметры указаны в статье, а какие выбраны нами

См. таблицу в YAML-конфигах:
- проверочный: [rl_de_comparison_check.yaml](./configs/rl_de_comparison_check.yaml)
- пилот 10D (3 повтора): [rl_de_comparison_pilot_10d.yaml](./configs/rl_de_comparison_pilot_10d.yaml)
- основной 10D (30 повторов): [rl_de_comparison_main_10d_30runs.yaml](./configs/rl_de_comparison_main_10d_30runs.yaml)
- RL-DE v2 (стагнация, 10D, 30 повторов): [rl_de_stagnation_v2_10d_30runs.yaml](./configs/rl_de_stagnation_v2_10d_30runs.yaml)
- основной шаблон: [rl_de_comparison_main_template.yaml](./configs/rl_de_comparison_main_template.yaml)

Для каждого параметра указан `source`:

- `article`
- `existing_implementation`
- `assumption`

Это сделано, чтобы не приписывать статье неуказанные параметры.
Например, конкретные границы функций и технические детали реализации
(`binomial`, `clip_to_bounds`) отмечены как `assumption`/`existing_implementation`,
а не как параметры, гарантированно заданные текстом статьи.

## 5. Как обеспечивается честное сравнение

Для всех алгоритмов в одном эксперименте фиксируются одинаковые:

- размерность
- границы поиска
- размер популяции NP
- F и CR
- бюджет вычислений (MaxFEs)
- критерии остановки
- определение результата
- правило генерации seed

Если одинаковые начальные популяции задаются напрямую, это фиксируется в конфигурации.  
Если нет, используется общий seed и одинаковая процедура инициализации.

## 6. Как проверяется воспроизводимость

Для каждого запуска сохраняются:

- алгоритм, функция
- полная конфигурация
- seed оптимизатора
- seed RL-агента / random selector
- версии Python/NumPy/thefittest
- лучшее решение и лучшее значение
- фактическое число вычислений
- история сходимости
- для Random-DE: история стратегий
- для RL-DE: состояния, действия, награды, Q-таблица

## 7. Как считаются показатели

Подготовлены функции:

- среднее best value
- стандартное отклонение (`ddof` явно задаётся в конфиге)
- минимум/максимум
- ранги алгоритмов с явным правилом tie-handling (средний ранг при равенстве)
- частоты выбора стратегий RL по стадиям (`early/middle/late`)

## 8. Длительные серии и защита от потери результатов

Пакетный запуск выполняется через `experiments/batch_run.py` и поддерживает:

1. Отдельный JSON-файл на каждый запуск (`runs/<function>/<algorithm>/run_XXX_seed_YYY.json`).
2. Немедленное сохранение результата после завершения запуска.
3. Режим продолжения `--resume` c проверкой целостности run-файлов:
   - совпадение алгоритма/функции/run_index/seed;
   - совпадение размерности, границ и бюджета;
   - конечность лучшего значения;
   - корректность длины историй;
   - для RL-DE — число шагов RL и диапазон наград.
4. Пропуск только полностью валидных запусков (без повторного включения в статистику).

## 9. Ограничения текущего этапа

1. На этом шаге **не выполняется** полная серия 30 запусков по всем функциям.
2. RL-состояние в текущей версии определяется только по доле использованного бюджета.
3. Технические детали RL-DE (одно действие на поколение, награда по доле строгих улучшений) соответствуют текущей реализации, но не заявляются как полностью однозначно заданные статьёй.
4. Git commit может отсутствовать, если запуск идёт вне git-репозитория.
5. Основной шаблон конфигурации содержит поля, которые нужно явно выбрать перед большой серией (размерность/бюджет/NP).
